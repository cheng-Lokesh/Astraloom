# MVP Database Schema

The Supabase migrations live at:

- `supabase/migrations/0001_mvp_core_schema.sql`
- `supabase/migrations/0002_mvp_evidence_chain_contracts.sql`

This schema is intentionally minimal but must preserve the MiroFish evidence chain:

- `seed_contexts` is the first user-generated product object.
- `key_people` comes next for structured person confirmation.
- `agent_profiles`, `relation_edges`, `simulation_runs`, `events`, `claims`, and `reports` are defined early so future Codex tasks do not invent incompatible table names.
- `simulation_ticks` stores tick snapshots before events are interpreted as reportable claims.
- `feedback_log` stores post-report calibration feedback for claims, agents, relation judgments, strategy usefulness, and overall run quality.
- `payments`, `support_tickets`, and `consent_events` are included because paid AI reports require support, refund, privacy, and consent traceability from the start.
- `users` is the whitepaper account anchor, while `profiles` remains for compatibility with earlier app code.

Current app behavior:

- `/intake` saves a local browser draft first.
- `/sync` keeps local drafts working and can write user-authored records when Supabase is configured and the user is authenticated.
- Current browser-side sync is intentionally limited to tables with user-manage RLS: `seed_contexts`, `key_people`, and `support_tickets`.
- System-owned or payment-owned records stay backend-only under current RLS: `agent_profiles`, `simulation_runs`, `events`, `claims`, `reports`, and `payments`.
- `/server-writers` shows the backend writer boundary for `agent_profiles`, `relation_edges`, `simulation_runs`, `events`, `claims`, `reports`, and `payments`.
- `/api/system-writers/status` returns only configuration booleans and writer states. It must not expose `SUPABASE_SERVICE_ROLE_KEY` or any other secret.
- `/server-writers/contracts` and `/api/system-writers/contracts` expose read-only system writer contracts for generated artifacts, payment entitlement, and consent audit records.
- `/server-writers/dry-run` and `/api/system-writers/dry-run` validate future writer request shapes and gates while always returning `wouldWrite=false`.
- `/server-writers/guardrail` and `/api/system-writers/guardrail` expose read-only execution policy for future writer auth context, audit, idempotency, rollback, and rollout gates.
- `/server-writers/adapter` and `/api/system-writers/service-role-adapter` expose an inert service-role adapter boundary that never creates a client or writes rows.
- `/server-writers/audit` and `/api/system-writers/audit` expose a read-only future `writer_audit_events` model without adding a migration or writing audit rows.
- `/server-writers/idempotency` and `/api/system-writers/idempotency` expose a read-only future `writer_idempotency_keys` model without adding a migration or reserving keys.
