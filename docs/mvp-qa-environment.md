```powershell
Copy-Item .env.example .env.local
```

Fill only these fields for the first authenticated MVP test:

```env
NEXT_PUBLIC_APP_URL=http://localhost:3000
NEXT_PUBLIC_SUPABASE_URL=<your Supabase project URL>
NEXT_PUBLIC_SUPABASE_ANON_KEY=<your Supabase anon public key>
```

```env
SUPABASE_SERVICE_ROLE_KEY=
ENABLE_SYSTEM_WRITERS=false
ENABLE_AI_GENERATION=false

STRIPE_SECRET_KEY=
OPENAI_API_KEY=
```

## 4. RLS Boundary Verification

The MVP boundary must stay strict.

Client-writable tables:

- `seed_contexts`
- `key_people`
- `feedback_log`
- `support_tickets`

Browser read-only tables:

- `agent_profiles`
- `relation_edges`
- `simulation_runs`
- `simulation_ticks`
- `events`
- `claims`
- `reports`
- `payments`
- `consent_events`

Manual Supabase check:

1. In Supabase, ensure RLS is enabled on every table listed above.
2. Confirm `seed_contexts`, `key_people`, `feedback_log`, and `support_tickets` have `for all` policies scoped to `auth.uid() = user_id`.
3. Confirm generated/payment tables only have `for select` policies scoped to `auth.uid() = user_id`.
4. Do not add insert/update/delete policies to generated/payment tables until server writer implementation is reviewed.

## 6. Manual Product Flow

Use the app in this order:

1. `/intake`: enter one main question, choose Track A or Track B, choose a time window, add a few related people, and acknowledge privacy.
2. `/people`: confirm at least one extracted person or manually add one.
3. `/agents`: verify the user self, optional parallel selves, confirmed NPC placeholders, and read-only ecology preview.
4. `/runs`: verify the run is a disabled shell and does not call AI.
